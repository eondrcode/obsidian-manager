# Device management implementation

- Fixed types: computer, tablet and phone. Each type holds one or more **named presets**; this installation binds to one preset and stores only that binding locally. Device identity is local and no longer carries configuration.
- Binding: `boundPresetId` lives in device-local storage alongside the device id. On start, an invalid/missing binding falls back to the first preset of the detected type and shows a one-line notice; changing the device type rebinds the same way. A refreshed platform identifier renames the existing device record instead of creating a duplicate.
- Scoped data: plugin enable/delay, Ribbon list and takeover flag, appearance (theme + explicit CSS snippet states). Install sources, import/export, troubleshoot, groups, tags and delay definitions stay global.
- Delay wait notice: `DelayWaitNotice` mirrors AstroScope's WaitMessage.js — the caller supplies seconds and an info string (`{seconds}` is substituted), default off via `DELAY_WAIT_MESSAGE`, countdown duration = largest delay + extra seconds, and never shown while delayed start itself is off.
- Call chain: `Manager.onload → synchronizePlugins → await DeviceManager.initialize (identity + normalize + binding + applyEffective) → enableDelay → layout ready → reconcileDevicePlugins → drainDelayQueue → applyRibbonSettings`.
- Save chain: editors → `saveSettings → DeviceManager.capture → (persistedSettings) → saveData`. While editing a non-bound preset, `DeviceManager.project` swaps its settings into memory, `capture` writes them into that preset, and `persistedSettings` restores the live values before `saveData`, so data.json never keeps another preset's values.
- Scope UI: `DeviceScopeBar` renders one shared dropdown (manager filter-field style) on 插件总览 / 外观总览 / 边栏编排, grouped by device type and listing named presets. The Devices page manages the type, preset CRUD, the local binding and the informational device list.
- New classes: `DeviceManager` owns identity, preset selection, projection and persistence; `DevicePanel` owns preset/binding/device UI; `DeviceScopeBar` owns the shared selector. Pure preset functions own validation, snapshots and runtime projection. No dependency on the font loader.
- Design assessment / 设计结论：无破坏。Existing object-oriented ownership is preserved. DOM is built with Obsidian APIs (`createEl`, existing Better Manager classes); the custom dropdown reuses the manager's filter menu and is fixed-positioned so scrolling containers cannot clip it.
- Migration: management starts disabled. Legacy single-preset data is wrapped into arrays; legacy per-device overrides are folded once into the first preset of that device's type and then dropped. Missing plugins and mobile-incompatible plugins are retained in presets but never loaded on unsupported devices; the manager itself and ignored plugins are excluded.
- Sync: presets and device names travel with plugin data; identity and preset binding stay local. Changes from another device take effect after plugin reload. Concurrent file synchronization still follows the sync provider's conflict rules.
- Verification: `npm run check` (tsc + eslint on `src/devices` + 21 model/runtime tests), production build, isolated empty-vault CDP checks, and a physical Android check over adb/WebView CDP.
