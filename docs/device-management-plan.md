# Device management implementation

- Fixed presets: computer, tablet and phone. Device identity is local to the installation; preset selection falls back to the Obsidian platform type and can be corrected manually. Mobile identity uses a hashed Capacitor `Device.getId()`; desktops keep a UUID in local storage.
- Two scope layers: a device type is the global layer, an individual device is the local one. Type presets store full scoped data; device overrides stay sparse and only capture the categories that device actually changed. Untouched categories keep following the type, and later type edits only reach non-overridden categories.
- Scoped data: plugin enable/delay, Ribbon list and takeover flag, appearance (theme + explicit CSS snippet states). Install sources, import/export, troubleshoot, groups, tags and delay definitions stay global.
- Delay wait notice: `DelayWaitNotice` mirrors AstroScope's WaitMessage.js — the caller supplies seconds and an info string (`{seconds}` is substituted), default off via `DELAY_WAIT_MESSAGE`, and never shown while delayed start itself is off.
- Call chain: `Manager.onload → synchronizePlugins → await DeviceManager.initialize (identity + normalize + applyEffective) → enableDelay → layout ready → reconcileDevicePlugins → drainDelayQueue → applyRibbonSettings`.
- Save chain: editors → `saveSettings → DeviceManager.capture → (persistedSettings) → saveData`. While editing a foreign scope, `DeviceManager.project` swaps the scoped settings into memory, `capture` writes them into that scope, and `persistedSettings` restores the live values before `saveData`, so data.json never keeps another device's values.
- Scope UI: `DeviceScopeBar` renders one shared dropdown (manager filter-field style) on 插件总览 / 外观总览 / 边栏编排. Type entries configure the type; device entries configure that device; the selection is shared across those three tabs. A reset button clears a device's overrides. The Devices page itself only manages identity, this device's type and the device list.
- New classes: `DeviceManager` owns identity, scope selection, projection and persistence; `DevicePanel` owns the device list/preset draft UI; `DeviceScopeBar` owns the shared selector. Pure preset functions own validation, merge resolution, snapshots and runtime projection. No dependency on the font loader.
- Design assessment / 设计结论：无破坏。Existing object-oriented ownership is preserved. DOM is built with Obsidian APIs (`createEl`, native `optgroup`/`option`), with existing Better Manager classes and no new CSS. Touch interactions use native controls, not card dragging.
- Migration: management starts disabled; all three presets inherit existing settings, including the current appearance snapshot. Enabling is explicit in the UI. Missing plugins and mobile-incompatible plugins are retained in presets but never loaded on unsupported devices; the manager itself and ignored plugins are excluded.
- Sync: presets, device names and overrides travel with plugin data; identity stays local. Changes from another device take effect after plugin reload. Concurrent file synchronization still follows the sync provider's conflict rules.
- Verification: `npm run check` (tsc + eslint on `src/devices` + 17 model/runtime tests), production build, and isolated empty-vault CDP checks. Real touch gestures require a real mobile device.
